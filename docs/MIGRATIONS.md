## הפקודות

```bash
npm run migrations:check                       # השער הסטטי — בלי מסד, בלי סודות. רץ ב-CI
npm run migrations:status                      # מה נחת, מה לא, ומה יש בלדג'ר בלי קובץ
npm run migrations:plan  -- --phase <id>       # תוכנית קריאה-בלבד לפאזה אחת
npm run migrations:apply -- --phase <id> --yes # החלה
```

`migrations:status` · `plan` · `apply` דורשים `DATABASE_URL` (מחרוזת החיבור
מלוח הבקרה של Supabase). **לעולם לא `NEXT_PUBLIC_SUPABASE_*`** — אלה ערכי anon
ואינם יכולים להריץ DDL. שום סוד לא מודפס; מוצג ה-host בלבד.

### דוקטרינת ההחלה

| כלל | למה |
|---|---|
| **פאזה אחת לריצה** | ריצה שמנחיתה שלוש ונופלת ברביעית משאירה מצב שאיש לא תכנן |
| **dry-run היא ברירת המחדל** | כתיבה דורשת `--yes`, שנכתב בכוונה |
| **פאזה היא אטומית** | כל הקבצים + שורות הלדג'ר בטרנזקציה אחת. חצי פאזה גרועה מכלום |
| **`foreign` נדחית** | היא פונה למסד אחר |
| **`applied` נדחית** | הרצה חוזרת היא בדיוק איך התוכנית החיה והמאושרת מתפצלות |
| **הלדג'ר הוא `supabase_migrations.schema_migrations`** | אותה טבלה שה-CLI כותב, כדי ששני הכלים לא יחלקו על המצב |

**אחרי החלה מוצלחת** — מעדכנים את הפאזה ל-`applied` ורושמים את `ledger`
ב-`supabase/phases.json`. פאזה שנחתה ונשארה `pending` מפצלת את התוכנית הבאה
מהמסד.

## השער הסטטי — שבעה כללים

כל אחד מהם עלה למישהו במשהו אמיתי. אף אחד אינו העדפת סגנון.

| | כלל | מה הוא תופס |
|---|---|---|
| M-01 | שמות | קידומת הקובץ **היא** סדר ההחלה. שם שלא נפרס מתמיין במקום שאיש לא חזה — כך `_vehicle_media_glb` מוין לפני הקובץ שיוצר את הטבלה שהוא כותב אליה |
| M-02 | כיסוי פאזות | כל מיגרציה בפאזה אחת בדיוק; פאזה שלא נחתה חייבת `why` |
| M-03 | מיפוי לדג'ר | פאזה `applied` חייבת לרשום את הגרסה שפרודקשן **באמת** נושאת |
| M-04 | rollback | כל מיגרציה **חדשה** מביאה את הביטול שלה (ratchet — הרשימה רשאית רק להצטמצם) |
| M-05 | אידמפוטנטיות | `create table/index` בלי `if not exists`; `create policy` בלי `drop policy if exists` לפניו |
| M-06 | הרסני | `drop table` · `truncate` · `DELETE`/`UPDATE` בלי `WHERE` |
| M-07 | `search_path` | פונקציה שנוצרת חייבת נעיצה; `reset` אסור |

**מה השער לא רואה, ואומר זאת:** SQL שנבנה בתוך מחרוזת (`execute format(...)`)
בלתי-נראה לכל שבעת הכללים. לא היפותטי — בריפו אח נעיצת `search_path` של שתי
פונקציות בוטלה בדיוק ככה ואף שער לא ראה. הכלי מסמן `warn dynamic` ולא מפיל:
להכריע מה SQL דינמי עושה זו עבודת קריאה, לא עבודת regex.

השער מאומת במוטציה — הסרת כלל מפילה את `test/migrationsGate.test.ts`.

## הטמעה — embeddings

```bash
npm run knowledge:status              # האם הקורפוס מוטמע, והאם בכלל אפשר
npm run knowledge:embed -- --yes      # הרצת ה-backfill
```

**נמדד 31.08.26: ‏30 מתוך 30 שורות נושאות `embedding IS NULL`.**

השליפה היא vector-first עם נפילה לחיפוש מילות-מפתח בעברית. כל עוד אין וקטורים,
המוח רץ **כולו** על הנפילה — מדויקת ב-30 שורות, ומפסיקה להיות מדויקת ככל שהקורפוס
גדל. **מצב הכשל שקט:** התשובות נעשות מעורפלות, שום דבר לא נדלק באדום.

הסקריפט הוא **נהג ולא מנוע**: לוגיקת ההטמעה כבר חיה במקום אחד —
`brain/embeddings.ts` מאחורי `POST /api/embed`, מוגן-אדמין, עם כתיבת
service-role. סקריפט שהיה מממש מחדש קריאות Voyage וליטרלים של pgvector היה
**מנוע הטמעה שני** עם הדריפט שלו.

דרוש: `EMBED_ADMIN_TOKEN` (המסלול fail-closed — בלעדיו 503 לכולם),
`VOYAGE_API_KEY` ו-`SUPABASE_SERVICE_ROLE_KEY` בפריסה שמונהגת.
`MIAME_SITE_URL` ברירת מחדל `https://www.miame.co.il`.
